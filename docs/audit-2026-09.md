# Production-readiness audit — September 2026 (register)

> **What this is.** The handover register for the external production-readiness
> audit of `@perssonify/editor` **v1.77.0** (Markdown Studio), dated
> **18 September 2026**: about 39,000 lines of TypeScript reviewed in thirteen
> passes, with the content-loss findings reproduced in a real browser. Its verdict
> was *not ready for production* — not for careless engineering, but because the
> domain did not serve the app, several ways of silently losing content were
> reproducible, nothing defended the library against the browser evicting its
> storage, and deploys were not gated on CI. The full report, with the evidence
> and reproduction for every finding, is at
> <https://claude.ai/artifact/QgXmDeiCJgCVh4haopBd6Y>. It raised **114 findings,
> A001–A114**. The code fixes landed on the `audit/production-readiness-fixes`
> branch (base `0fed016`); every commit cites the IDs it addresses, and the
> invariants they introduced are in [`CLAUDE.md`](../CLAUDE.md).
>
> **This file is the authoritative list of what remains.** [`backlog.md`](backlog.md)
> keeps the earlier audits and the design backlog; where anything there disagrees
> with a row below, this register wins. When you close an item, update its row
> here in the same change.

**Statuses.** **Fixed** — the defect is gone and a test pins it (each commit says
how its guard was mutation-tested). **Partial** — the code side is done or
mitigated; the note says exactly what remains. **Owner** — a setting, an account,
a document or a decision: nothing can be merged to close it. **Deferred** —
deliberately left for a separate change.

## Owner actions (not code)

Every item here is an account, a setting, a document or a decision. The code side
of each is already merged. [`deployment.md`](deployment.md) has the step-by-step
for the first six.

1. **Point the domain at the app** (A001, blocker). markdownstudio.com shows a
   registrar parking page. Confirm the registration is held by a company account,
   remove the for-sale listing, add `markdownstudio.com` and `www` to the Vercel
   project and create the DNS records. The scheduled **Uptime** workflow stays red
   until then; afterwards, replace it with an external monitor that pages a person.
2. **Gate production on CI** (A005, blocker). Protect `main` (a ruleset requiring
   a review and the `verify` and `e2e` checks) and turn on Vercel **Deployment
   Checks** — or switch off automatic production deploys and promote green builds
   by hand. Until then a red merge ships to every user. While in Vercel, confirm
   the build uses Bun 1.4.0 (`packageManager` is set; A014).
3. **Deploy the move banner to the old origin, then redirect** (A004, blocker).
   Browser storage is per origin, so users of markdowneditor.perssonify.com will
   find an empty library on markdownstudio.com. This build shows a "we've moved —
   download a full backup" banner, and Help ▸ "Moving your library", only on the
   old host (`LEGACY_APP_HOST`). Deploy it there, leave it up for a grace period,
   then redirect.
4. **Redirect subdomain and Labs page** (A002). Create markdownstudio.perssonify.com
   as a **301 redirect** to markdownstudio.com (a second hosted copy would give
   users a second, separate library); build the Labs detail page
   (labs.perssonify.com/markdownstudio) from [`marketing/`](../marketing/); point
   Labs' links at markdownstudio.com once step 3 has run its course.
5. **Claim npm** (A006). Create the `perssonify` organisation under a company
   account with a second owner and 2FA required; set up trusted publishing
   (preferred) or a granular `NPM_TOKEN`; create the GitHub `npm` environment with
   required reviewers. Until the scope is claimed, anyone can publish under the
   name the README tells people to install. Releases then go only through
   `publish.yml` on a `vX.Y.Z` tag.
6. **Create the security mailbox** (A007). security@markdownstudio.com is named by
   `/.well-known/security.txt`, SECURITY.md and the issue templates but does not
   exist. Route it to at least two people and test it. `security.txt` expires on
   2027-09-29 (the unit tests go red a month before, as a reminder).
7. **Relay abuse and spend controls** (A010). `Sec-Fetch-Site` stops other web
   pages, not curl: to non-browser clients the import relay is a bounded proxy
   (4 MB, 25 s, global-unicast targets only). Add a Vercel firewall rate-limit rule
   on `/api/import`, spend alerts, a saved search over its one-line-per-request
   log, and know where the kill switch is — [`import-relay.md`](import-relay.md),
   [`runbooks/relay-abuse.md`](runbooks/relay-abuse.md).
8. **Decide when to enforce the CSP** (A068). It ships report-only and
   hash-pinned; anti-framing is already enforced. `bun run e2e:csp` runs the build
   with the policy enforced and must stay at zero violations. Consider a
   `report-to` endpoint first if you want field data.
9. **Set the embed allowlist** (A072). Every embed build served from an origin
   that holds user documents needs `VITE_EMBED_ALLOWED_ORIGINS` set at build time;
   without it the bridge falls back to the framer the browser reports.
10. **Legal pages** (A075). A product privacy policy, terms and imprint, written
    with counsel: browser-local storage, the relay (it sees IP addresses and the
    imported address; hosting logs), log retention, and one legal entity name —
    the product currently shows "Perssonify Labs", `APP_BRAND` "labs.perssonify"
    and "© Markdown Studio". Engineering then adds `/privacy`, `/terms` and
    `/imprint` and links them from the About footer, Settings ▸ Privacy, the relay
    prompt and Help ▸ Offline & privacy.
11. **Trademark and launch brand** (A080). At least two unrelated products use
    "Markdown Studio" publicly. Clear the name, decide the launch brand, and decide
    whether the Perssonify branding stays in the starter "About Perssonify" folder
    and the About footer.
12. **Accessibility statement** (A081). Publish a statement with a conformance
    target. The fixes were measured against WCAG 2.x AA criteria (contrast, reflow
    at 400 %, label in name, focus visible); the Admin-gate half of A081 is done.
13. **Declare a browser floor** (A097). Tailwind v4 already needs Safari 16.4,
    Chrome 111 and Firefox 128. With a declared floor, engineering can build the
    unsupported-browser message (older Safari currently shows a blank page if it
    cannot parse the CSS).
14. **Name owners** (A112). An owner per area — persistence and sync, the
    converter, UI and accessibility, the library and embed, operations and
    security — and a `CODEOWNERS` file so the required reviews route to them.
15. **Choose an error-reporting service, if any** (A009, optional). The app keeps
    a local, redacted diagnostics ring and exposes `setErrorReporter`; nothing
    leaves the device today. Sending reports anywhere is a product and privacy
    decision.

## Deferred engineering work

From the partial and deferred rows. None of these blocks a launch.

- **Large documents** (A083). Every projection still re-converts the whole
  document. The cheap fixes cut a 1.6 MB document's markdown→rich projection from
  ~0.4 s to ~0.1 s and rich→markdown from ~5 s to 1.6–3.5 s (jsdom). Next:
  incremental projection or a worker; the next hotspot is `cleanHtmlForTurndown`
  (~1.3 s).
- **Images as blobs** (A086). The storage limit is now the browser's real quota,
  with a clear "Storage full" state; images embedded as data URIs still count
  against it.
- **Scale of the other surfaces** (A087, A088). The Cards board renders
  progressively but is not virtualised (that would fight its masonry order); the
  map's physics at ~2,000 notes is untouched.
- **Two-space hard breaks in exports** (A051). Needs a decision on the app's
  `breaks: true` dialect first.
- **Unsupported-browser message** (A097). The lookbehind that made the entry
  chunk a SyntaxError is gone and a TypeScript-parser scan keeps it out; the
  message waits for the owner's browser floor.
- **Internationalisation** (A099). Right-to-left text renders correctly in both
  panes; a translation layer for the ~330 hard-coded UI strings, a per-document
  language for exports, and `print-export.ts`'s hard-coded `lang="en"` remain.
- **Firefox and WebKit** (A100). The browser campaign runs Chromium only; a CI job
  for the other engines is proposed, not built, so the iOS-specific paths (the
  `pagehide` stash, safe areas, eviction) have no real-browser proof.
- **One editor per page** (A106). The stores are module singletons; per-instance
  stores are not built. The limit is documented (README, integration guide).
- **Behavioural coverage of the big UI files** (A108). Coverage now counts all of
  `src`; every fix brought tests, but `PerssonifyEditor.tsx`, `FindReplace.tsx`
  and `GraphView.tsx` remain thinly covered.
- **Types and lint** (A109). ESLint with the React hook rules is at 0 errors
  (253 warnings, 199 of them `no-explicit-any`); `noImplicitAny` is not on (12 errors
  in 4 files).
- **Split `PerssonifyEditor.tsx`** (A110). Recommended as its own pull request.
- **Dependency majors** (A113). Tiptap is 3.31.3 as one set and peer ranges are
  bounded; marked 12→18, React 19 and TypeScript 7 (also mermaid 12, vitest 5,
  jsdom 30, lucide 1.x, nanoid 6, undici 8) are scheduled, not done.
- **Toolchain range.** `engines.node` admits 22.12, but ESLint 10 needs
  `^20.19 || ^22.13 || >=24`: tighten the range or pin the Node that CI and
  contributors use.

**Decided, not deferred** (recorded in [`decisions.md`](decisions.md)): the
one-click URL import stays (A003); the embed keeps its database name, because
renaming it would orphan every embed user's library (A072). **Known limits that
stay:** titles containing `|` or `]` cannot be wiki-linked (A059); lists and
paragraphs inside a table cell flatten — GFM cannot hold them — and are reported
(A044); where a host's CSP blocks `blob:` workers, Find's regex runs on a guarded
main-thread fallback instead of the terminable worker (A061).

## Found while reconciling the documentation (not audit findings)

Checking every document against the code turned up defects the audit did not
list. None is fixed yet; each needs a code change and a test.

1. **The full app is frameable at `/embed.html` on the production deploy**
   (security, relates to A068). `vercel.json` exempts `/embed.html` from the
   enforced `frame-ancestors 'none'` / `X-Frame-Options: DENY`, which is right for
   a self-hosted embed build. But the production deploy is `dist-app/`, which has
   no `embed.html`, so the SPA rewrite answers `/embed.html` with the FULL app —
   without the anti-framing headers. Any site can frame the complete app, with the
   origin's library, at that address. Fix: stop exempting `/embed.html` unless an
   embed build is actually deployed there (or return 404 for it). The link builder
   also emits embed snippets pointing at `${origin}/embed.html`, which on
   markdownstudio.com is this full app.
2. **Unmounting the editor can write a blank draft over a stored document**
   (data safety, relates to A024). `releaseEditor` writes the cached draft through
   `patchDocById`, which has no blank guard; the crash stash skips a blank draft
   but the write-through does not. The blank-over-content backstop is bypassed for
   a host that unmounts the editor inside the autosave window.
3. **A newer-version document gets the "editor is empty" message** (UX, relates to
   A021). The schema lock parks the save status `blocked`, and both ⌘S
   (`describeUncommittedSave`) and the autosave toast key on `blocked` alone, so
   they tell the user the editor is empty. Only the status bar distinguishes the
   lock ("Newer version — read-only").
4. **The first-run documents' `[[Welcome]]` links are broken** — and, since A058,
   visibly marked as broken for every new user. Since 1.76.0 the Welcome
   document's title follows its H1 ("Markdown Studio") rather than a pinned
   "Welcome", so the links from Changelog and About Perssonify resolve to nothing.
   `starter-documents.test.js` assumes the seed still pins "Welcome" and cannot
   see it. Fix the links (or the title) and make the test derive titles the way
   the app does.
5. **The crash screen's "Export my documents" skips the export rules** (relates to
   A079, A021). `utils/emergency-backup.ts` builds its own envelope: it keeps the
   full `origin` (the raw imported input and the clipboard alternates) and has no
   `schemaVersion`. `toExportEnvelope`, used by every other export, also keeps
   `ingestReport`, which can hold the pre-ingest HTML.
6. **`clearLocalData()` leaves a note's text behind** (relates to A079, A103):
   without `{ preferences: true }` it keeps `pf:card-draft` (the Cards composer's
   draft), and that key is not namespaced by a host's `storageConfig`.
7. **A direct URL-import timeout is treated as a CORS failure.** The code checks
   for `AbortError`, but `AbortSignal.timeout` rejects with `TimeoutError`, so a
   slow site leads to the relay question instead of a "timed out" message.
8. **User-facing copy outside the docs that still overstates**: the PWA install
   description says "Client-only, works offline" (`vite.app.config.ts`); Help's
   Offline & privacy says to install the app to work offline (it works offline
   after one visit, installed or not); the About page mentions importing PDF,
   which the app cannot do.
9. **Stale comments in the code**: the first-run seeding comment in
   `PerssonifyEditor.tsx` still says the starter documents avoid "a second,
   headless" import path (import is now headless); `snapshot-store.ts`'s eviction
   comment says a doc's newest snapshot is never evicted (a deleted document's is,
   after 30 days); `WorkspacePanel.tsx` calls the divider "left-edge"; an
   `import-relay.test.js` case title still says "non-browser open-proxy call".
