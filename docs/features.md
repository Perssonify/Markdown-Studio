# Features — What This System Actually Does

The single most-read doc after the [README](README.md). Each feature is self-contained: what it does, who can use it, where it starts in code, the happy-path flow (files in order), the data it touches, and known limits.

> **Roles:** This is a single-user app that runs in the browser — no accounts, and no server copy of your documents (the only server code is the opt-in URL-import relay). There is **no permission model** — every capability is available to whoever has the browser tab open. "Who can use it" is therefore "any user" throughout, except where a feature is gated by *mode* or *screen size*. See [auth.md](auth.md).

**Where state lives** (referenced constantly below):
- `useDocumentStore` — [src/store/documentStore.ts:748](../src/store/documentStore.ts#L748) — documents, active doc, tabs, save status, counts, storage handle.
- `useUIStore` — [src/store/uiStore.ts:153](../src/store/uiStore.ts#L153) — view mode, sidebar/graph/find toggles, sync mode.
- `useEditorStore` — [src/store/editorStore.ts:92](../src/store/editorStore.ts#L92) — active formatting state, link index, backlinks, graph data.

## Editing

### 1. Dual-pane editing

- **What:** Edit raw markdown (left) and rich text (right) simultaneously; changes in one pane appear in the other.
- **Entry point:** `EditorLayout` ([src/ui/EditorPanes.tsx:691](../src/ui/EditorPanes.tsx#L691)), rendering [src/ui/CodeMirrorPane.tsx](../src/ui/CodeMirrorPane.tsx) and [src/ui/TiptapPane.tsx](../src/ui/TiptapPane.tsx).
- **Happy-path flow** (you type in the markdown pane):
  1. CodeMirror fires its change handler → `handleMdChange()` in [src/hooks/useDocumentLifecycle.ts:242](../src/hooks/useDocumentLifecycle.ts#L242).
  2. The change is debounced, with a ceiling so the other pane keeps up during continuous typing; both delays come from the measured cost of recent projections (see [src/hooks/sync-schedule.ts](../src/hooks/sync-schedule.ts)).
  3. `syncMdToHtml()` runs — [src/engine/useSyncEngine.ts:41](../src/engine/useSyncEngine.ts#L41): `quickHash(md)` guard → `engine.mdToHtml(md)` → `tiptapRef.setHTML(html)`.
  4. Tiptap re-serializes to its canonical ProseMirror JSON; `onCanonicalChange(editor.getJSON())` fires ([src/engine/useSyncEngine.ts:97](../src/engine/useSyncEngine.ts#L97)).
  5. Autosave is scheduled; after `AUTOSAVE_MS` the doc is written to IndexedDB.
- **Data read/written:** Reads/writes `activeDoc.canonical` (PM JSON) in memory; persists to the `documents` IndexedDB store on autosave.
- **Edge cases:** An empty rich pane is a genuine clear and propagates to the markdown — a focus-based "is this spurious?" heuristic silently reverted real deletions and was removed. What stops a blank editor from wiping a stored document is the persistence boundary: `saveActiveDoc` refuses to write a blank canonical over stored content (terminal `blocked` status) unless the clear was explicit. The hash gates (`quickHash`, [:62](../src/engine/useSyncEngine.ts#L62) / [:124](../src/engine/useSyncEngine.ts#L124)) and the rich pane's doc-node identity check prevent echo loops, and each is committed only after its conversion succeeded; if you ever see content fail to sync, those gates are the first suspects.
- **IME / voice dictation:** an IME (and Windows Voice dictation) streams text through a `compositionstart → update → end` cycle; dispatching into an editor mid-composition aborts it and drops what was streamed. Both panes expose `isComposing()`, and a projection defers for **the pane it writes**, and only that pane — checking both froze the mirror for a whole utterance. A stuck flag expires (`COMPOSITION_STALL_MS`), because an undo dispatched into a live composition destroys it with no `compositionend`. Document-**leaving** paths end the composition instead of waiting for it: they are about to hydrate a different document over both panes, so waiting means the dictated text is destroyed. Measured against a real composition driven through CDP, not a mocked boolean. [src/__tests__/composition-guards.test.js](../src/__tests__/composition-guards.test.js), `e2e/cases/journeys.mjs`.
- **Right-to-left and non-Latin text:** every paragraph, heading, list item and cell in the rich pane, and every line in the markdown pane, takes its direction from its own text (`dir="auto"` through view-only decorations — `BidiAuto` in [src/extensions/BidiAuto.ts](../src/extensions/BidiAuto.ts) and [src/extensions/cm-bidi.ts](../src/extensions/cm-bidi.ts) — so nothing is written into the document). Word counts segment Chinese, Japanese, Thai, Lao, Khmer and Myanmar text with `Intl.Segmenter`. The interface itself is English-only; a translation layer has not been built.
- **Related code:** [data-pipeline.md — Stage 3](data-pipeline.md#stage-3--bidirectional-sync-the-heart), tests in [src/__tests__/sync-engine.test.js](../src/__tests__/sync-engine.test.js).

### 2. View modes (Markdown / Rich Text / Split)

- **What:** Show only the markdown pane, only the rich-text pane, or both side by side.
- **Who:** Any user, at any width. Below 768px wide, Split stacks the panes one above the other — but only when there is height for two (500px or more), or on a touch device held upright; a landscape phone keeps them side by side rather than squeezing two editors into a strip (`splitShouldStack`, [src/ui/split-layout.ts](../src/ui/split-layout.ts)).
- **Entry point:** `ModeSwitcher` ([src/ui/ModeSwitcher.tsx:34](../src/ui/ModeSwitcher.tsx#L34)) → `useUIStore.setMode`. Mode constants: `MODES` = `{ MD, HTML, SPLIT }` ([src/constants.ts:34](../src/constants.ts#L34)).
- **Flow:** `setMode(m)` → `useUIStore.mode` updates → `EditorLayout` shows the panes for that mode → `PerssonifyEditor` persists it as `editorMode` in prefs through `usePersistPreferences` ([src/editor/useEditorBoot.ts:30](../src/editor/useEditorBoot.ts#L30)).
- **Edge cases:** the toolbar compacts when its OWN width drops below `TOOLBAR_COMPACT_BP` (1080px, measured with a `ResizeObserver`, so a library mount in a narrow container compacts too — [src/constants.ts](../src/constants.ts)); the ☰ menu collapses below 768px ([src/hooks/use-mobile.ts](../src/hooks/use-mobile.ts)); the split stack follows the width-and-height rule above. Below 450px of height the standalone shell lets the page scroll instead of shrinking the editor to nothing (usable at 400% zoom).

### 3. Menu bar (File · Edit · Insert · View · Format · Tools · Help)

- **What (v1.9.0):** A desktop-style application menu bar ([src/ui/MenuBar.tsx](../src/ui/MenuBar.tsx)) replaces the old document tab strip. Every item reuses an existing editor handler — `handleAction(type)` (import/export/copy/clear/prompt/graph), `dispatch(cmd)` (undo/redo + all Insert/Format commands), `handleSave`/`handleRevertDoc`/`handleNewDoc`/`handleCloseTab`, and the sidebar/graph/search/settings toggles — so it is a presentation layer only. Rendered in the `chrome === "full"` slot in [src/PerssonifyEditor.tsx](../src/PerssonifyEditor.tsx); embed/minimal chrome is unaffected.
- **Document switching:** there is no tab strip — switch documents from the **Workspace panel's Files tab** (`onSelect → handleSwitchDoc`), which highlights the active doc; the active title is shown on the right of the menu bar. Save + Undo/Redo also remain as quick buttons on the formatting toolbar.
- **Removed:** the previous full-screen *focus mode* (button, `⌘\` shortcut, and the fixed-position overlay) was dropped in favour of this streamlined chrome. A new, lighter **Focus mode** (chrome-dimming, not an overlay) was reintroduced in v1.35.0 — see "Reading & typography" below.

### 3a. Reading & typography (v1.35.0)

- **What:** Reader-comfort controls that apply to **both** panes: **font size** (S/M/L/XL), **line height** (Tight/Normal/Relaxed/Loose), **reading width** (Full/Narrow/Medium/Wide — caps the text column for comfortable line lengths), **spellcheck** toggle, and **Focus mode** (dims the menu bar, toolbar, status bar, and pane headers to 25% opacity so the document leads; any dimmed region returns to full opacity on hover/focus).
- **Who:** Any user. **Entry points:** Settings ▸ "Reading & typography" ([src/ui/SettingsSheet.tsx](../src/ui/SettingsSheet.tsx)); Focus mode also has a View-menu checkbox ([src/ui/MenuBar.tsx](../src/ui/MenuBar.tsx)).
- **How it works:** All five prefs live in `useUIStore` (persisted `pf:font-size`, `pf:line-height`, `pf:reading-width`, `pf:spellcheck`, `pf:focus-mode`). Font size / line height / reading width are pushed as CSS custom properties (`--editor-font-size`, `--editor-line-height`, `--reading-width`) on the editor split container ([src/ui/EditorPanes.tsx](../src/ui/EditorPanes.tsx)); `.ProseMirror`/`[data-md-preview]` and CodeMirror's `.cm-content` read them (styles.css + `cmTheme()` in [src/ui/CodeMirrorPane.tsx](../src/ui/CodeMirrorPane.tsx)). Reading width caps the **content column** (centered), not the flex pane, so the split-divider math is untouched. Spellcheck rides a CodeMirror `contentAttributes` Compartment (live) and both Tiptap `editorProps.attributes` objects. Focus mode toggles a `.pf-focus` class on the `PerssonifyEditor` container (which encloses all chrome); dimming is **opacity/transition only** so the `h-dvh` viewport lock never reflows.

### 4. Text & block formatting

- **What:** Bold, italic, underline, strikethrough, superscript, subscript, inline code; headings H1–H6, ordered/unordered/task lists, blockquote, code block, horizontal rule.
- **Entry point:** the toolbar (`EditorToolbarComponent`, [src/ui/Toolbar.tsx:350](../src/ui/Toolbar.tsx#L350)) — one tab stop, with the arrow keys moving between its buttons (`useRovingFocus`) — or keyboard shortcuts ([src/hooks/useKeyboardShortcuts.ts](../src/hooks/useKeyboardShortcuts.ts)).
- **Happy-path flow:** Toolbar button → `dispatch(cmd)` → `useFormatDispatcher` ([src/formatting/useFormatDispatcher.ts:139](../src/formatting/useFormatDispatcher.ts#L139)) picks the target pane via `getTargetPane()` ([:155](../src/formatting/useFormatDispatcher.ts#L155)):
  - **Rich-text pane active** → `dispatchToTiptap()` ([:344](../src/formatting/useFormatDispatcher.ts#L344)) runs Tiptap commands.
  - **Markdown pane active** → `dispatchToMd()` ([:512](../src/formatting/useFormatDispatcher.ts#L512)) edits the CM6 text directly, on EVERY selection range — so Select ▸ All headings followed by Bold bolds every heading, not just the first. `mdWrapBy` wraps or unwraps each range through `changeByRange` ([src/formatting/md-format-utils.ts](../src/formatting/md-format-utils.ts)); the dispatcher's `mdPrefixLine`/`mdSetHeading` rewrite only each selected line's prefix, so the selection survives for the next command. Clear formatting in this pane unwraps emphasis and formatting tags but keeps code, images, links, URLs and maths (`clearMdFormatting`).
- **Data:** Operates on the active pane's content; result flows through the sync engine into canonical PM JSON.
- **Indent / outdent (`Cmd+]` / `Cmd+[`, toolbar):** these mean **list nesting**, in both panes. Rich pane → `sinkListItem` / `liftListItem` with the item type taken from the selection (`taskItem` inside a checklist, `listItem` otherwise — hardcoding the latter made indent dead in every checklist). Markdown pane → CodeMirror's `indentMore`/`indentLess`, gated by `mdIndentable` ([src/formatting/useFormatDispatcher.ts](../src/formatting/useFormatDispatcher.ts)) to list lines and lines inside a fenced block. Markdown has no paragraph indent — four leading spaces on a paragraph *is* an indented code block — so on anything else both panes no-op rather than change what the block is.
- **Strikethrough round-trip:** TipTap renders `<s>`; turndown's core is CommonMark and this project does not load `turndown-plugin-gfm`, so an unmatched element is silently reduced to its text. The `strikethrough` rule in [src/engine/turndown-rules.ts](../src/engine/turndown-rules.ts) emits `~~…~~`. Without it, striking text in the rich pane was destroyed by the next sync and lost on export, with no fidelity warning — strikethrough is native Markdown, so nothing classed it as a loss.
- **Keyboard:** document chords — ⌘B/⌘I/⌘U/⌘E, ⌘K, ⌘⇧1–6, ⌘]/⌘[ and ⌘Z's cancel of a pending projection — act only when the caret is inside a pane AND the Editor view is showing. Typed in the Cards composer, a library rename box or the map's search they are left to that field; they used to format the document hidden underneath. Global chords (find, replace, search, save, new, workspace panel, map, cards) work from anywhere in the editor. **AltGr is never a shortcut** (`isAltGraphInput`, [src/utils/alt-graph.ts](../src/utils/alt-graph.ts); CodeMirror's Ctrl+Alt bindings are filtered by `dropAltGraphChords`, the rich pane's by `AltGraphPassthrough`), so `[`, `]` and `\` can be typed on German, Nordic or French layouts. The cost: Tiptap's undocumented Ctrl+Alt+digit heading chords no longer fire on Windows/Linux (⌘⇧1–6 do). Tab right after a list keeps its old meaning (`ListKeymapNoTab`) rather than Tiptap 3.31's move-into-the-list.
- **Edge cases:** Toolbar active-state for the markdown pane is **regex-based** (`queryState`, [src/formatting/useFormatDispatcher.ts:689](../src/formatting/useFormatDispatcher.ts#L689)) — it can mis-detect nested markers (see `isSubmarker` at [src/formatting/md-format-utils.ts:271](../src/formatting/md-format-utils.ts#L271)).
- **Related:** [src/__tests__/md-format-utils.test.js](../src/__tests__/md-format-utils.test.js).

### 4a. Interactive task lists (v1.36.0)

- **What:** `- [ ]` / `- [x]` render as **clickable** checkboxes in the rich pane (TipTap `TaskList`/`TaskItem`); toggling a box updates the Markdown, and inline markdown inside an item (bold, links) is preserved. Nested task lists round-trip.
- **Entry point:** Toolbar "Task List" button, Format ▸ Task list, or type `- [ ] ` in the Markdown pane. Gated on the `taskLists` feature (Settings ▸ Features).
- **How it works:** No preprocessor pass — marked's gfm list tokenizer detects tasks, and `build-marked.ts` overrides the renderer (gated on `taskLists` + gfm) to emit `<ul data-type="taskList"><li data-type="taskItem" data-checked="…">` (suppressing the default disabled `<input>`), which keeps each item's inline markdown. `TaskList`/`TaskItem` are registered in both `TiptapPane.tsx` and `serialize-doc.ts` `SERIALIZE_EXTENSIONS`. Turndown's `taskListItem` rule reads `data-checked` and re-emits `- [x]`/`- [ ]`, indenting nested items.
- **Related:** [src/__tests__/task-lists.test.js](../src/__tests__/task-lists.test.js).

### 5. Tables

- **What:** Insert tables via a grid picker; add/delete rows & columns; column alignment.
- **Entry point:** Toolbar table button → `TableGridPicker` ([src/ui/TableGridPicker.tsx:20](../src/ui/TableGridPicker.tsx#L20), up to 8×6). In-table editing surfaces `TableBubbleMenu` ([src/ui/TableBubbleMenu.tsx:68](../src/ui/TableBubbleMenu.tsx#L68)).
- **Flow (markdown pane):** Table commands route to [src/formatting/md-table-ops.ts](../src/formatting/md-table-ops.ts) — `mdParseTableAtCursor` ([:33](../src/formatting/md-table-ops.ts#L33)) parses the pipe table, ops mutate the 2-D array, `renderTable` ([:317](../src/formatting/md-table-ops.ts#L317)) re-emits aligned markdown. Rows are split the way the renderer splits them (`cellSeparators`, [:244](../src/formatting/md-table-ops.ts#L244)): an escaped `\|` is cell content and a `[[Doc|Alias]]` wiki link is one unit, so adding a row never cuts a cell in two. An explicit `:---` is kept, and a table inside a list item keeps its indentation.
- **Flow (rich-text pane):** Tiptap `@tiptap/extension-table` commands via `dispatchToTiptap`. Column alignment (`:--` / `:-:` / `--:`) is an `align` attribute on the cells (`TableCellAlign`, registered in both `TiptapPane.tsx` and `SERIALIZE_EXTENSIONS`), so it survives the rich pane.
- **Edge cases:** Deleting the last row/column deletes the whole table (`mdDeleteRow`, [:131](../src/formatting/md-table-ops.ts#L131); `mdDeleteColumn`, [:172](../src/formatting/md-table-ops.ts#L172)). A cell's markdown comes from the same conversion as the rest of the document, so strikethrough, sized images and maths survive in cells, and every pipe in a cell is written `\|`. A GFM cell is one line: `<br>` is kept, but a list or a second paragraph inside a cell flattens and merged cells cannot be written — the fidelity report flags both.
- **Related:** [src/__tests__/md-table-ops.test.js](../src/__tests__/md-table-ops.test.js), [src/__tests__/formatting-table-cells.test.js](../src/__tests__/formatting-table-cells.test.js).

### 5a. Equation authoring dialog (v1.37.0)

- **What:** Insert ▸ Formula (block) / Inline formula and the toolbar Σ menu open a **LaTeX dialog with a live KaTeX preview** instead of a bare browser prompt. As you type, the formula renders below the input; a KaTeX parse error is surfaced as a message. ⌘/Ctrl+Enter (or the Insert button) commits.
- **Entry point:** `useDialog().equation(title, { display })` — a promise-based method on the shared `DialogApi` ([src/ui/DialogProvider.tsx](../src/ui/DialogProvider.tsx)), rendered as `EquationDialog` ([src/ui/Dialogs.tsx](../src/ui/Dialogs.tsx)) in `PerssonifyEditor`. On confirm the caller dispatches `insertMathBlock` / `insertMathInline` (the same math commands as before), so round-trip and the `$…$`/`$$…$$` output are unchanged.
- **Editing existing equations:** unchanged — click a rendered math node and edit its source inline via the `MathNodes` node view. KaTeX is lazy-imported, so the dialog adds nothing to the initial bundle, and a failed load is tried again next time rather than remembered for the session (`cachedImport`). The standalone app imports KaTeX's stylesheet once; a library consumer imports `katex/dist/katex.min.css` itself ([integration-guide.md](integration-guide.md#the-stylesheet-and-why-importing-it-is-safe)).

### 5b. Callouts & collapsible details (v1.38.0 / v1.39.0)

- **Callouts:** `> [!NOTE]` / `[!TIP]` / `[!IMPORTANT]` / `[!WARNING]` / `[!CAUTION]` blockquotes render as themed admonition cards (Insert ▸ Callout, or type the marker). Inline markdown inside is preserved; they round-trip to `> [!TYPE]` markdown. Gated on the `callouts` feature (Settings ▸ Extensions). `build-marked.ts` overrides the blockquote renderer; the Callout node ([src/extensions/Callout.ts](../src/extensions/Callout.ts)) is registered in both extension arrays; the turndown `callout` rule sits after `plainDiv` (LIFO). It's not Markdown, so it round-trips as **raw HTML** (marked passes the block through; the Details/Summary nodes re-parse it; turndown re-emits `outerHTML`) — the Markdown pane shows the raw `<details>` for that block. `details`/`summary` are whitelisted in `KNOWN_ELEMENTS` so imports keep them. Related: [src/__tests__/details.test.js](../src/__tests__/details.test.js).

### 6. Colors, highlight, font family, alignment

- **What:** Text color, highlight color, font-family selector, and text alignment (left/center/right/justify).
- **Entry point:** [src/ui/Toolbar.tsx](../src/ui/Toolbar.tsx) (color/highlight/font controls), shortcuts `Cmd+Shift+L/E/R/J` for alignment (`alignMap`, [src/hooks/useKeyboardShortcuts.ts:202](../src/hooks/useKeyboardShortcuts.ts#L202)).
- **Edge cases:** These are **decorative** commands, and they divide into two cases:
  - **Colour, highlight and font family survive as inline HTML.** In the markdown pane they wrap the selection in `<span style="…">` ([src/formatting/useFormatDispatcher.ts](../src/formatting/useFormatDispatcher.ts)); in **Clean** sync mode that HTML is stripped, the toolbar shows a warning toast ([src/ui/Toolbar.tsx](../src/ui/Toolbar.tsx)) and the fidelity report flags the loss.
  - **Alignment is not representable in either mode.** `setTextAlign` sets a paragraph attribute that no turndown rule emits, and a `text-align` style on an inline `<span>` is inert, so alignment is app-only: it does not survive a round-trip through the markdown pane or any export. It is the one formatting feature in this list with no markdown or inline-HTML carrier. `computeFidelity` ([src/store/fidelity.ts](../src/store/fidelity.ts)) counts it as an attribute loss so the status-bar indicator reports it; the toolbar and Format ▸ Align tooltips say so up front. Changing a Markdown feature setting re-projects only the markdown pane of a document the current mode cannot carry losslessly, so the switch itself no longer strips alignment (or, in Clean mode, colour).

### 7. Links (inline) & link bubble menu

- **What:** Insert/edit inline `[text](url)` links.
- **Entry point:** `Cmd+K` (the `promptLink` branch, [src/hooks/useKeyboardShortcuts.ts:162](../src/hooks/useKeyboardShortcuts.ts#L162)) or toolbar; editing popup is `LinkBubbleMenu` ([src/ui/LinkBubbleMenu.tsx:17](../src/ui/LinkBubbleMenu.tsx#L17)). ### 8. Find & Replace

- **What:** A floating, draggable find/replace panel with a live match counter, Next/Prev navigation, inline replacement preview, and option toggles: **match-case**, **whole-word**, and **regex**. A **Find | Replace** segmented control at the top of the panel switches modes (Find mode shows **Find + Find all**; Replace mode shows **Replace + Replace All**). It can also apply **formatting to every match** — bold/italic/underline/highlight or a case change (UPPER/lower/Title) — in Replace mode only. Replace, Replace All and Format matches are hidden in read-only mode.
- **Who:** Any user. `Cmd+F` opens Find mode. **⌥⌘F** (Ctrl+Alt+F off the Mac) opens Replace mode, and so does **Ctrl+H** on Windows/Linux — ⌘H never reaches the page on macOS (the system hides the app), and on a layout where AltGr+F types a character (Hungarian `[`, for one) that keystroke types it. The same shortcuts switch the panel's mode from inside the panel. The panel opens on whichever pane the cursor was last in. Close from the ✕ in the panel header or with `Esc`.
- **Position:** The panel is `position: fixed`; it **opens centered over the content** and **remembers its last dragged position** across open/close and sessions (`pf:fr-pos`, restored before paint in a `useLayoutEffect`, clamped on-screen).
- **Entry point:** [src/ui/FindReplace.tsx](../src/ui/FindReplace.tsx); state `useUIStore.showFindReplace`. Matching lives in [src/formatting/find-engine.ts](../src/formatting/find-engine.ts) and [src/formatting/find-worker.ts](../src/formatting/find-worker.ts).
- **Flow — one matcher:** `compileFindQuery` turns the query and options into one pattern, and every consumer — the count, Next/Prev, Find all, Replace, Replace All, Format matches, the scrollbar ticks and BOTH panes' highlighters — uses the same `MatchSet`, cached per query and document revision. The highlighters only draw the ranges they are handed (`setSearchHighlight(spec)`); they never run the pattern themselves. The markdown pane is searched as one string, with `^`/`$` meaning line start/end; the rich pane is searched per text node, so a match never spans a node boundary (where the marks change). Whole word is Unicode-aware — letters, digits and combining marks of any script count as word characters. Find all multi-selects every match in the MD pane (`EditorState.allowMultipleSelections`). Option toggles persist in localStorage (`pf:fr-*`).
- **Regex safety:** a regex runs in a Web Worker with a 1.5 s timeout, after which the worker is terminated and the panel says the pattern is too slow — a catastrophic pattern cannot freeze the page. Literal searches stay on the main thread. Where no Worker can be created (a host page whose CSP blocks `blob:` workers), a guarded main-thread fallback runs with a 250 ms budget after refusing the classic nested-quantifier shape; that check is a heuristic, and the Worker is the guarantee.
- **Replacing:** in regex mode the replacement is expanded from the ORIGINAL match (`expandReplacement`: `$1`, `$&`, `$<name>`, …), so a context-dependent pattern such as `\d+(?=px)` replaces what it counted; a literal search inserts the replacement verbatim. Replace All is ranged changes over exactly the (scoped) matches the count shows, capped at 10,000 matches ("10000+"). In the rich pane Replace inserts plain text through a ProseMirror transaction (never parsed as HTML, never a regex over serialized HTML), and Format matches ▸ Highlight merges into each run's text style instead of wiping its colour or font.
- **Scope / format filter (MD):** A collapsible funnel of per-region chips that each cycle **off → only → exclude**, grouped Structure (headings / code / links) and Formatting (bold / italic / strike / highlight), applied by `applyMdScope` (persisted `pf:fr-scope`). Headings and code come from the shared CommonMark fence tracker, so a `# comment` inside a fenced block counts as code, not as a heading. The count, scrollbar markers and Replace All all honour this filter. **Match ticks** are drawn over the active pane's scrollbar (`MatchScrollbar`, portaled to `document.body` because the panel's `backdrop-blur` is a containing block for fixed children).
- **Select all headings:** Set the **Headings** scope chip to *only* with an empty search box — the "Format matches" row targets every heading at once for one-click bulk styling or recasing (CM: `mdHeadingRanges`; rich: heading text nodes).
- **Edge cases:** An invalid regex shows an inline "ERR" and doesn't throw; a zero-length match advances by one code point instead of looping in place.
- **Related:** [src/__tests__/find-engine.test.js](../src/__tests__/find-engine.test.js), [src/__tests__/find-replace-panel.test.jsx](../src/__tests__/find-replace-panel.test.jsx).

## Sync modes (Clean vs Styled)

- **What:** Controls whether the `<span style="…">` / `<div style="…">` carrier is written back to markdown. That carrier — and **only** that carrier — is what the switch decides.
  - **Clean** — the style carrier is dropped, so text colour, highlight and font family are stripped; output is portable GFM.
  - **Styled** — the carrier is preserved inline, so those three survive the round trip.
  - **Neither mode touches** underline, subscript, superscript or an image's width/height: their rules live in `addBaseRules`, which both Turndown instances receive, so they are written as `<u>`/`<sub>`/`<sup>`/`<img … width>` either way. **Nor does either mode carry text alignment**, which has no rule at all. Measured per case in [src/__tests__/clean-vs-styled.test.js](../src/__tests__/clean-vs-styled.test.js); `fidelity.ts` classifies from these same rule tables, and got it wrong in both directions before that test existed.
- **Entry point:** Pills in the pane header (`SyncModePills`, [src/ui/EditorPanes.tsx:88](../src/ui/EditorPanes.tsx#L88)); state `useUIStore.syncMode` (defaults to `"styled"`, [src/store/uiStore.ts:168](../src/store/uiStore.ts#L168)).
- **Where the branch lives:** in `syncHtmlToMd`, `convert` picks the converter ([src/engine/useSyncEngine.ts:149](../src/engine/useSyncEngine.ts#L149)) — `syncMode === "styled" ? engine.htmlToMd : engine.htmlToCleanMd`. The two converters are two Turndown instances built by `createMarkdownEngine` ([src/engine/useMarkdownEngine.ts:161](../src/engine/useMarkdownEngine.ts#L161)): `tdInline` (styled, adds the inline-style rule) vs `tdClean` (base rules only). Both share the markdown escaper, which backslash-escapes literal text that would otherwise turn into markup on the next pass (a `<` before a tag-like character, `&` before an entity, `N)` at a line start — and, only while their feature is on, a `$` exactly where it would open a formula, `~~`, and a recognised curly group). Ordinary prose such as `a < b`, `Tom & Jerry` or `$5` stays as typed.
- **Paste Styled:** a **persisted preference, on by default** ([src/ui/EditorPanes.tsx](../src/ui/EditorPanes.tsx), `pf:paste-styled`) — pasting keeps the source's formatting. It used to default to stripping and disarm itself after one paste; that one-shot reset was removed, since with styled as the default it turned the preference off the first time it was used. **Holding ⇧ inverts it for a single paste.** The modifier does not come from the paste event (`ClipboardEvent` carries no `shiftKey` — measured); `TiptapPane.handlePaste` reads `view.input.shiftKey` and passes it explicitly.

### 12. Auto-save & session restore

- **What:** Edits persist automatically; the last active document reopens on reload.
- **Entry point:** Autosave interval `AUTOSAVE_MS` (5000 ms, [src/constants.ts:63](../src/constants.ts#L63)). Restore: `useDocumentStore.initialize()` ([src/store/documentStore.ts:290](../src/store/documentStore.ts#L290)) reads the manifest and the `lastActiveDocId` pref. It is re-entrant: an editor that is unmounted and mounted again (inside a host app) re-opens the open document for the new instance instead of seeding another copy, and unmounting is itself a document-leaving path that flushes and stashes what was typed.
- **Data:** Writes `doc` records + `__manifest` + `__prefs` to IndexedDB — see [database.md](database.md).
- **Storage limit:** the app imposes no cap of its own — the limit is the browser's quota (read with `navigator.storage.estimate()`), plus an optional host `maxBytes`. A write the browser refuses for lack of space becomes the terminal status `full` (**"Storage full — not saving"**): autosave stops retrying until a document is deleted or a real edit is made, and the toolbar's Save can retry once space is freed. See [runbooks/storage-quota-exceeded.md](runbooks/storage-quota-exceeded.md).
- **Reads that fail are errors, not "not found".** An adapter's `get()` returns null only for a genuine miss and throws `StorageReadError` otherwise, so the save path fails closed — it writes nothing over a document it could not read — and boot skips an unreadable document instead of stopping. The document list is checked against the stored ids and rebuilt from the documents when it is missing, unreadable or out of step.
- **A failed save stays visible.** A failed autosave is routed `error` → `editing` after 3s so the re-arm effect fires, which meant that for most of each retry cycle the status bar read "Unsaved changes" — the reassuring message — while saving was failing over and over. `saveError` outlives that transition (cleared only by a save that lands) and the bar reads **"Save failed — retrying"**. The terminal states say what they are rather than nothing: `"blocked"` (the blank-over-content refusal) reads **"Empty editor — not saving"**, `"conflict"` reads **"Changed in another tab — not saving"**, and `"full"` reads **"Storage full — not saving"**. None re-arms autosave; a later real edit resumes it. A document written by a newer build of the app opens read-only (**"Newer version — read-only"**) rather than blank, and nothing can save over it. ⌘S reports "saved" — and fires a host's `onSave` — only when the write actually committed.
- **Multi-tab conflict:** if another tab/window saves a newer version of the doc you're editing, this tab refuses to save over it (last-writer-wins would silently discard that tab's work). The status bar shows a persistent **"Changed in another tab — not saving"** and the save loop stops re-firing; copy anything you need and reload. A later edit here resumes normal saving. The same check covers renames, a card's pin/colour and host bridge patches, and a reload of the conflicted tab keeps the other tab's work (the unload stash records the revision each draft was based on). This is a visible surface over the guard, not a live cross-tab sync (that stays on the backlog). [src/store/documentStore.ts](../src/store/documentStore.ts) `saveActiveDoc` (`"conflict"` status).
- **Keeping the library (standalone app):** after the first successful save the app asks the browser to keep its storage (`navigator.storage.persist()`), and Settings ▸ Storage & backup shows whether it is persisted and how much is used. A reminder appears when the last full backup is over 7 days old. If IndexedDB comes back empty while a small localStorage record (`pf:library-canary`) remembers documents, the starter documents are NOT seeded — a notice explains the loss and offers Import a backup, Version history or Start fresh. Safari/iOS users get a tip to install the app, which exempts it from Safari's 7-day storage limit. A persistent **"Not saving"** banner shows whenever browser storage is unavailable (in embeds too, but not with a host-injected storage adapter). [src/store/storage-durability.ts](../src/store/storage-durability.ts).
- **Title provenance:** a document remembers whether its title was a real user rename (`titlePinnedByUser`) rather than guessing from the string, so a doc you deliberately name "Untitled 5" keeps that name while an accidental placeholder still heals from your first heading. [src/store/document.ts](../src/store/document.ts) `resolveDocTitle`.

### 12a. Version history (recoverable snapshots)

- **What:** A safety net that keeps prior content versions per document so an
  overwrite, an accidental clear, a bad replace-all, or even a delete can be
  undone — and these survive a reload. Open via **Tools ▸ Version history**.
- **How it captures:** `saveActiveDoc` snapshots the previous stored content
  before overwriting it (throttled to ~one per 90s per doc, but a large content
  shrink — the "got wiped" signature — always snapshots); `deleteDoc` snapshots
  the doc before removing it; a card edit that would drop formatting keeps the
  version it replaces.
- **How it restores:** *Restore* replaces the current document (your current
  content is snapshotted first, so the restore is itself reversible); *As new*
  recreates the version as a separate document (used to recover deleted docs,
  listed under "Other & deleted documents"). Deleting a version asks first, and
  says so when it is the last copy of a deleted document. In read-only mode
  Restore, As new and Delete are disabled, and restoring in place is refused.
- **Entry point / data:** [src/store/snapshot-store.ts](../src/store/snapshot-store.ts) —
  a **sidecar IndexedDB** (`perssonify-snapshots`), independent of the main
  document store, bounded by per-doc count (20) + a global byte budget + age
  (30 days). A deleted document's pre-delete snapshot is subject to the same
  caps, so deleted content expires, and **Erase history** on the delete toast
  removes it at once. A host's `storageConfig` can namespace or disable this
  database. UI: [src/ui/VersionHistorySheet.tsx](../src/ui/VersionHistorySheet.tsx).
  Falls back to an in-memory ring when IndexedDB is unavailable.

## Import / export

### 13. Import & export

- **What:** Import `.md`/`.markdown`/`.txt`/`.html`/`.htm`/`.json`/`.docx`; export Markdown, HTML, or ProseMirror JSON; copy any of those to clipboard.
- **Entry point:** the **File** menu ([src/ui/MenuBar.tsx](../src/ui/MenuBar.tsx)) — Import…, Export ▸, Full backup — dispatched through `handleAction` in [src/editor/useEditorActions.ts](../src/editor/useEditorActions.ts). (`ActionBar.tsx` no longer exists; the menu bar replaced it.)
- **Dropping a file on the editor imports it** (`EditorLayout` in [src/ui/EditorPanes.tsx](../src/ui/EditorPanes.tsx), `onDragOver`/`onDrop` → PE's `handleFileDropImport`). There was no drop handler anywhere in `src/`, so a file dropped on either pane got the browser default: the tab navigates to the file and everything typed since the last autosave is gone — the one gesture that leaves no draft, no undo and no snapshot. Only drags carrying `Files` are intercepted; a text/HTML drag inside the document still belongs to CodeMirror and ProseMirror. The `preventDefault` happens even with no importer wired, since losing the document is not an acceptable way to say "we can't import this". Pinned by [src/__tests__/editor-file-drop.test.js](../src/__tests__/editor-file-drop.test.js).
- **Flow (import):** File chosen/dropped → the `import` branch of `handleAction` expands archives, converts `.docx`, and reads everything else with `getFileContentAndFormat` (→ `detectFormat`, [src/store/import-export.ts:66](../src/store/import-export.ts#L66)) → `importItems` → `createDoc` → `ingest()` ([src/store/ingest.ts:488](../src/store/ingest.ts#L488)). Each file is converted **headlessly** (`captureIngestHeadless`: the ingest HTML parsed against the live editor's schema, or the identical `headlessSchema()` when no editor is mounted) and persisted with `saveNewDoc` **without being activated** — the import never borrows the open editor, so a click in the library mid-import cannot swap content between documents. Import is a document-leaving path: it first flushes and saves the open document, then opens the first imported file through `handleSwitchDoc`. A backup envelope whose id is already in the library is imported under a fresh id, so both copies are kept.
- **Flow (export):** `exportAsMarkdown`/`exportAsHtml`/`exportAsJson` ([src/store/import-export.ts](../src/store/import-export.ts)). Markdown export respects the current sync mode; JSON export wraps the document in the `_format: "perssonify-document"` envelope built by `toExportEnvelope` ([src/store/import-export.ts:290](../src/store/import-export.ts#L290)), which carries the schema version and leaves out `origin.raw` and the clipboard `alternates` — text you may have deleted since.
- **PDF / print:** "PDF / Print…" renders the rich document into a hidden iframe with a print stylesheet and opens the browser print dialog (use "Save as PDF"). Fidelity matches HTML export. Implemented by `printHtmlDocument` in [src/store/print-export.ts](../src/store/print-export.ts). In the app and the embed, printing the page itself (⌘P) prints the rich pane — even in Markdown-only view — with the chrome hidden.
- **Word (.docx):** "Word (.docx)" tokenizes the document's Markdown with marked's lexer and maps tokens to Word elements via the (dynamically imported) `docx` library — headings, paragraphs, nested lists, blockquotes, code, tables, rules, inline formatting. [src/store/docx-export.ts](../src/store/docx-export.ts). Images/math/diagrams fall back to source text.
- **Word (.docx) import:** A `.docx` upload is converted to HTML by the (dynamically imported) `mammoth` library, then fed to the existing `format:"html"` ingest branch — so it gets the same sanitize (`sanitizeForIngest` keeps inlined `data:` raster images, strips scripts) and residual-report (`analyzeHtml`) treatment as any HTML import. PE's import loop branches on `.docx` **before** the text-reading path (a Word file read as text is binary garbage). [src/store/docx-import.ts](../src/store/docx-import.ts) `convertDocxToHtml`. Best-effort/lossy: headings, bold/italic, lists, tables, and embedded raster images convert; Word equations (OMML), text boxes, and complex layout do not. Embedded images inline as base64, so a small `.docx` can expand past the 5 MB import cap once images are embedded. Related: [src/__tests__/docx-import.test.js](../src/__tests__/docx-import.test.js).
- **Archives:** Import `.zip`/`.tar`/`.tgz`/`.gz` (directory structure → folders; `__MACOSX`, entries inside hidden directories and non-text files are skipped, while a dot-prefixed file name is kept); export a folder, the current multi-select, or **all documents** as a ZIP of Markdown files (`handleExportFolder`/`handleExportDocs` → `exportDocsToZip` → `readDocuments`, one IndexedDB transaction → `buildZipAsync`, which compresses file by file and yields to the event loop → `downloadBlob`). A document that cannot be read is reported, never silently left out of the ZIP. Decompression-bomb bounds and **entry-path normalization** (`normalizeArchivePath` strips absolute roots, Windows drives, and `..`/`.` segments so a crafted archive can't traverse the folder tree or a storage key) live in [src/store/archive.ts](../src/store/archive.ts).
- **Full backup (restorable snapshot):** Export → **“Full backup (.zip) — restorable”** (`export-backup-zip`, `exportDocsToZip(..., { canonical: true })`) writes every document as the full `perssonify-document` JSON envelope — canonical ProseMirror content plus title, id, tags, metadata, and timestamps — in its folder path. Re-importing the ZIP restores those documents exactly (styled colors/highlights/fonts round-trip losslessly, unlike Markdown export); a document whose id is still in the library comes back as a copy beside it rather than over it. A rudimentary, fully-local portability/version-control system. The time of the last non-empty full backup is recorded (`pf:last-full-backup`) for the backup reminder.
- **Timestamped export filenames:** Every exported ZIP is suffixed with a local `YYYYMMDD-HHMMSSmmm` stamp (`exportTimestamp` in [src/store/import-export.ts](../src/store/import-export.ts)) so successive backups sort chronologically and never collide.
- **Import from URL:** "Import from URL…" fetches a Markdown/HTML/text file **or a `.zip`** client-side ([src/store/url-import.ts](../src/store/url-import.ts)) — https/http only, no cookies, 15 s timeout, streamed cap (**5 MB** text / **20 MB** archive; the archive extractor keeps its own decompression-bomb bounds) — then routes through the same `ingest()` sanitize pipeline. Because a backend-less app can't read cross-origin responses that lack CORS headers, the dialog also offers an always-works paste fallback and steers the user to it on a CORS failure. UI: [src/ui/UrlImportDialog.tsx](../src/ui/UrlImportDialog.tsx).
  - **Provider-aware links** ([src/store/import-url-normalize.ts](../src/store/import-url-normalize.ts)): **Google Drive** file share links (`/file/d/…/view`, `open?id=`) are rewritten to `drive.usercontent.google.com/download` — which sends permissive CORS headers, so public Drive files (and zips) import directly; **GitHub** `/blob/` → `raw.githubusercontent.com`; **Dropbox** → `dl=1`; **Google Docs/Sheets** → best-effort HTML/CSV export. A Drive **folder** link (no public no-auth download) fails with an actionable message (download it as a zip, or share the files).
  - **Preview & select:** after fetching, a preview step lists what will be imported — for a zip, every text entry with its folder path, **all selected by default and individually deselectable** — before anything is written.
  - **Shareable import links:** the preview surfaces a copyable `…/?import_url=<url>` deep link; opening it re-launches the importer **pre-filled but does NOT fetch** — a shared link must never make a visitor's browser hit an attacker-chosen address on load, so the visitor presses Fetch themselves and then confirms in the preview. The parameter is read by the app shell (`App.tsx`) during render and stripped from the URL, never by the editor component — otherwise a library consumer's own query string would open dialogs inside their editor. Top-level only — never auto-imports from a host page's query param into an embed. Builder: `buildImportShareLink`; the parameter is read in [src/App.tsx](../src/App.tsx) and handed to the editor as the `initialImportUrl` prop, which opens the importer pre-filled.
  - **Import relay (Google Drive et al.) — opt-in:** hosts like Google Drive send no CORS headers to a real browser, so a direct fetch is blocked. The importer tries the **direct fetch first** (GitHub raw, Dropbox, and any `Access-Control-Allow-Origin` host resolve directly and never involve the relay). On a CORS/network failure it can retry through the app's own same-origin serverless function ([api/import.js](../api/import.js), `IMPORT_RELAY` in `url-import.ts`) — **but only with the user's consent**: the first time, it asks, saying that the server receives the address and that it may appear in the hosting provider's logs; the answer is remembered (`pf:import-relay`) and can be changed in Settings ▸ Privacy. Without a stored "allow" and a way to ask, the relay is never used. Because the relay lives on the app's own origin, no third party sees the request, and it is more reliable than the public CORS proxies it replaced. The function fetches only **global-unicast** addresses — an allowlist, checked **after DNS resolution** and again on **every redirect hop** — so private, loopback, link-local, CGNAT, cloud-metadata, multicast and reserved targets are refused, as is every IPv4-in-IPv6 wrapper except a plain `::ffff:` mapping (which is unwrapped and re-checked); the vetted IPs are **pinned to the connection via an undici dispatcher** so `fetch` can't be DNS-rebound between validation and connect (TOCTOU). Bodies are capped at 4,000,000 bytes (larger files get a 413 with a message the importer shows); cross-site browser requests are refused via `Sec-Fetch-Site`; CORS is pinned to the app's two exact origins; there is a best-effort per-IP rate limit; and every request emits one structured log line (the host, never the path or query). A non-browser client can still call it — it is a **bounded proxy**, and a platform rate limit and spend alerts are deployment setup. The allowlist and `assertPublicUrl` are covered by [src/__tests__/import-relay.test.js](../src/__tests__/import-relay.test.js). **Full developer guide — request path, threat model control by control, how to run and test it, every current limitation, and a prioritised hardening roadmap: [import-relay.md](import-relay.md).** The preview discloses when the relay was used (`viaProxy`). Deployments without the function (a non-Vercel host, or the embeddable library) simply fall through to the download-and-drag guidance. The `vercel.json` rewrite excludes `/api/*` so the function isn't swallowed by the SPA fallback.
- **Search:** The sidebar filter matches document titles, tags, **and body content**. A global search overlay (**⌘/Ctrl+⇧F**, [src/ui/SearchPanel.tsx](../src/ui/SearchPanel.tsx)) ranks every note by title/body match with highlighted snippets and keyboard nav; opening a result seeds the Find bar. Pure ranking in [src/store/search.ts](../src/store/search.ts).
- **Front matter:** A leading `---` … `---` YAML block round-trips through both panes as a read-only key/value card ([src/extensions/FrontmatterBlock.ts](../src/extensions/FrontmatterBlock.ts)); the preprocessor emits a placeholder node ([src/engine/preprocessor.ts](../src/engine/preprocessor.ts)) and a turndown rule restores the block. It is only taken as front matter when the line after the opening `---` looks like YAML (a key or a comment), so a document that merely starts with a thematic break keeps its prose; an entity typed in a value (`&amp;`, `&quot;`) is kept exactly as written.
- **Edge cases:** Files over **5 MB** are skipped with a warning (archives have their own bounds) — checked in `collectImportItems`, which the import branch of `handleAction` calls ([src/editor/useImportPipeline.ts](../src/editor/useImportPipeline.ts)).

### 13a. Autosave (browser-local)

- **What:** The document saves itself ~5s after you stop editing (persisting the canonical ProseMirror JSON, which is cheap — no markdown/HTML conversion on the save path). Manual ⌘S / Save remains as a redundant affordance. Implemented in [src/editor/useAutosave.ts](../src/editor/useAutosave.ts) (`AUTOSAVE_MS`).
- **Unload is its own data-loss path, and `beforeunload` alone does not cover it.** The handler does fire a best-effort autosave, but IndexedDB is asynchronous — `saveActiveDoc` awaits a read before it writes, so the page is gone before the write is even issued, and the in-memory draft cache does not survive a reload either. Measured: type a sentence, reload inside the autosave window, and it was on neither pane nor disk. localStorage is the only store that completes while a page is torn down, so the handler **also** writes a synchronous stash (`stashUnsaved`, `pf:recovery` — [src/store/crash-recovery.ts](../src/store/crash-recovery.ts)): the live canonical for the document the editor actually holds, plus every parked draft, honouring the same blank-over-content backstop. `initialize` adopts it via `takeStashed()` **before** activating a document, feeding the ordinary cached-draft path. Each entry records the revision its draft was based on and whether the tab was already in conflict, so a reload cannot turn a refused save into an overwrite; entries are merged per document, so a second tab's unload does not erase the first tab's stash. The stash is one-shot (one that survived its own restore would keep resurrecting itself over newer content), bounded to 2 MB newest-first, and expires after a week. It is wired to **`pagehide` as well**: iOS Safari does not fire `beforeunload` when a tab is swiped away.
- **Storage boundary:** Autosave writes **only** to browser storage (IndexedDB, or localStorage / the host `window.storage` shim as fallbacks) via the storage adapter. It never calls the host `onSave` callback — automatic persistence stays on-device. Documents are stored in the browser (IndexedDB) on this device: no account and no server copy. What does touch the network: the app's own files (and the service worker's update check); images a document references, which load from their hosts unless **Settings ▸ Privacy ▸ Block remote images** is on (a CSP `img-src` the app shell installs; it applies from the next load, and the page sends no `Referer`); user-initiated *Import from URL* fetches; and the **import relay** ([api/import.js](../api/import.js)), used only after the user agrees — asked once, remembered, changeable in Settings ▸ Privacy. Direct-fetchable hosts never touch the relay, and the download-and-drag path stays fully local. There is no analytics or telemetry: diagnostics stay in a local ring until the user copies them.

### 13b. Offline (PWA)

- **What:** The standalone app ([`vite.app.config.ts`](../vite.app.config.ts) via `vite-plugin-pwa`, `registerType: 'prompt'`) registers a service worker that precaches **every** JavaScript chunk — the lazy ones too (KaTeX, Mermaid, abcjs, Word export, …) — plus the CSS, woff2 fonts and icons, so after **one** online visit the app works fully **offline** across reloads, installed or not, and is installable.
- **Updates are prompted, never forced:** a new version installs and waits while the tab shows **"Update ready — Reload"**; nothing reloads a tab over someone's typing. A long-lived tab (typically an installed app) checks for a new version hourly while it is online and visible ([src/pwa/sw-updates.ts](../src/pwa/sw-updates.ts)). The boot watchdog in `index.html` clears caches and reloads only on evidence that the app's own files failed to load, and never offline.
- The embeddable library build ([`vite.config.ts`](../vite.config.ts)) and the iframe embed get **no** service worker.

### 12b. Pasting into the rich pane (styles kept by default)

- **What:** Pasting into the rich pane **keeps the formatting you copied** — bold, links, headings, lists, tables. Hold **Shift** while pasting to do the opposite once.
- **Why the default changed:** it used to strip styles by default, and the "Styled paste" switch was a *one-shot* — you armed it, pasted once, and it disarmed itself. Losing the formatting of something you deliberately copied is the surprising outcome, not the safe one. The switch is a persisted preference now (`pf:paste-styled`), and Shift **inverts** it rather than forcing styled (as `shiftKey || pasteStyled` the modifier could never change the outcome once the default was on).
- **Still sanitized:** "keeps styles" is not "keeps anything". A styled paste runs through `sanitizePastedHtml`; a stripped paste runs through `cleanPasteHtml`. Neither admits scripts or active content.
- **Where:** the "Styled paste" switch in the rich pane's header; `handleHtmlPaste` in [src/hooks/useDocumentLifecycle.ts](../src/hooks/useDocumentLifecycle.ts); default and persistence in [src/store/uiStore.ts](../src/store/uiStore.ts). Pinned by [src/__tests__/paste-styled.test.js](../src/__tests__/paste-styled.test.js).

### 13c. Import fidelity — reading the residuals

- **What:** When an import contains something the document model cannot represent, it is recorded as a **residual** (see [domain-glossary.md](domain-glossary.md)). The status bar shows the count; **clicking it opens the list**.
- **Why it is a button:** the count alone told the reader that some number of elements "could not be mapped to the current schema" and gave them no way to find out which — jargon plus a number, in an editor whose promise is that it does not quietly change your document. The per-item detail (type, tag, attribute, reason, position) was recorded on every import all along; it simply had nowhere to be read.
- **What it shows:** the items grouped into explained categories — *removed for safety* (scripts and active content), *no place in the document model*, *inline style not carried over*, *attribute not kept*, *may not survive a round-trip*, *comments not kept* (HTML comments, recorded as `html-comment`) — each with the element and where it was, and a plain statement that the original file was not changed. Each group is capped so a badly-formed import cannot turn the answer back into a wall.
- **Drift guard:** `RESIDUAL_KINDS` must have an entry for **every** `type` that `ingest.ts` pushes as a residual, or the dialog renders a raw slug — exactly the jargon it replaces. [src/__tests__/residuals-dialog.test.js](../src/__tests__/residuals-dialog.test.js) scrapes `ingest.ts` and fails if one is missing.
- **Accuracy matters more than the count.** `KNOWN_ELEMENTS`/`SCHEMA_OWNED_ATTRS` in `ingest.ts` must mirror the live schema. They had drifted behind `themeImage`, `Callout` and `SizedImage`, so the shipped welcome document — which *demonstrates* a `<picture>` theme image, a `> [!NOTE]` callout and a sized logo — opened reporting seven losses that never happen. Once the count became a readable list, the inaccuracy was obvious. [src/__tests__/residual-accuracy.test.js](../src/__tests__/residual-accuracy.test.js) pins it.
- **Known limit:** on the HTML/paste path `sanitizeForIngest` runs *before* `analyzeHtml`, so blocked elements (scripts, iframes, form controls) are removed and reported as nothing — the count under-reports there. The markdown path sees everything.
- **Sanitising:** inline styles are filtered against an allowlist — every value written into a `style` attribute goes through [src/engine/css-safety.ts](../src/engine/css-safety.ts), which refuses CSS escapes rather than decoding them — and `class`/`id`/`name` are stripped except `language-*`, `sr-only`, `wiki-link` and `perssonify-link`. Whenever a document is imported or loaded from storage, `sanitizeCanonicalNode` validates the attributes renderers write into styles: colour, highlight, font family, text and cell alignment, column widths and theme-image sources. Without a DOM parser, ingest fails closed (everything becomes text).
- **Entry point:** [src/ui/ResidualsDialog.tsx](../src/ui/ResidualsDialog.tsx), opened from [src/ui/StatusBar.tsx](../src/ui/StatusBar.tsx). `DocumentRecord.residuals` is typed `ResidualItem[]`.

- **Entry point:** **Tools ▸ Copy as Prompt** ([src/ui/MenuBar.tsx](../src/ui/MenuBar.tsx)) → handled by `handleAction`'s `prompt` branch ([src/editor/useEditorActions.ts:87](../src/editor/useEditorActions.ts#L87)) → `buildContextPrompt` ([src/integration/prompt-builder.ts:232](../src/integration/prompt-builder.ts#L232)). ## Wiki links & knowledge graph

### 15. Wiki links (`[[…]]`)

- **What:** Link one document to another by title or id; backlinks are tracked automatically.
- **Syntax:** `[[Document Title]]`, `[[Title|Display Text]]`, `[[Title#Heading]]`, `[[#Heading]]` (a heading in the current document), or a document id in place of the title. Inside a table cell the alias separator is written `\|`, the spelling GFM needs there (a bare `|` typed in a cell is escaped for you so the cell is not split); both spellings work everywhere. Titles containing `|` or `]` cannot be linked — that is the syntax itself.
- **Rendering:** a marked **inline extension** (`wikiLinkExtension`, [src/engine/wiki-link-marked.ts](../src/engine/wiki-link-marked.ts)) turns `[[…]]` into a link mark carrying `data-doc-link` / `data-anchor`. Because it runs only where marked lexes inline content, a `[[…]]` inside any kind of code — fenced, indented or a code span — stays literal. A bare `[[My_Doc]]` is shown verbatim, never re-read as emphasis.
- **Resolution — one resolver:** `resolveWikiLink` / `createWikiResolver` ([src/store/link-index.ts:193](../src/store/link-index.ts#L193)) try the whole `docLink#anchor` as a title first (so `[[C# Tips]]` finds the note "C# Tips"), then an exact id, then an exact title — NFKC-normalised, case-insensitive, whitespace-collapsed — and nothing partial. The link index, the click handler and the broken-link marking all use it, so the map, the backlinks and a click never disagree about where a link goes. A heading anchor is found by a Unicode-aware key (`normalizeHeadingAnchor` / `findHeadingByAnchor`), so non-Latin headings resolve too.
- **Entry point / flow:** `useLinkIndex` ([src/hooks/useLinkIndex.ts](../src/hooks/useLinkIndex.ts)) rebuilds the index via `buildLinkIndex` ([src/store/link-index.ts:248](../src/store/link-index.ts#L248)) when documents are added, removed or renamed, and splices in only the changed document after a content edit; `scanWikiLinks` ([:77](../src/store/link-index.ts#L77)) reads both rendered link marks and literal `[[…]]` text (skipping code). Clicks on links in the rich pane are delegated on `document` and resolved at event time, so they keep working after the editor remounts.
- **Broken links** are marked in the rich pane by a ProseMirror decoration (`UnresolvedWikiLinks`, [src/extensions/UnresolvedWikiLinks.ts](../src/extensions/UnresolvedWikiLinks.ts)) — judged live against the library, never written into the document — and drawn with a dashed underline.
- **Data:** Builds the four maps `forward / reverse / unresolved / contexts` — see [database.md#the-link-index-in-memory-not-persisted](database.md#the-link-index-in-memory-not-persisted).
- **Related:** [src/__tests__/links-resolution.test.js](../src/__tests__/links-resolution.test.js).

### 16a. Diagnostics console (bottom tray, admin-gated)

- **What:** A read-only diagnostics console — a REPL-style input + scrollback that runs a **curated** command set over the editor's existing read APIs. ### 17. Knowledge graph (the relationship map)

- **What:** A full-screen **relationship map** of the whole workspace — documents are nodes, `[[wiki links]]` are edges, folders are labelled containers. Single-document structure is **not** here: that is the Workspace panel's **Outline** tab (#15b), which stays visible beside the map (the overlay covers `<main>` only). An in-graph structure pane was tried and removed as a duplicate.
- **Layout — three DOCKED regions, nothing floats over the canvas:** a header, the map with one slim footer strip (legend · zoom −/%/+ · Fit), and a details rail — a right column on `lg+`, a docked bottom sheet below that, toggled from the header. Selecting a node on a narrow viewport opens the rail, or a tap would appear to do nothing. The map pane measures **only its own box** (`canvasRef` + `ResizeObserver`), so fit and focus are correct by construction. An earlier build pinned the inspector *over* the canvas while the camera fitted content to the full rect — the graph centred itself underneath the panel, and the note you selected was the one you could no longer see. Do not re-add an overlay over the canvas.
- **Physics runs in its own WORLD space** (`worldFor(n)`), never the viewport, so resizing a panel re-aims the camera instead of reheating the simulation and reshuffling the graph. A single mutate-in-place loop freezes on settle; a decaying `alpha` (`ALPHA_DECAY`/`ALPHA_MIN`) makes convergence deterministic, with a `MAX_FRAMES` backstop. Repulsion scales with the node **count**, not the world area.
- **Performance — the frame is the expensive half, not the physics.** A CPU profile of a 153-note settle never surfaced `stepOnce` or `placeLabels` (~1ms) while the frame measured a 44ms median, almost all of it style and layout for the SVG the render rewrites. Above 60 notes the layout advances several steps per rendered frame (`stepsPerFrame`, capped at 6): **108 rendered frames / 5.6s / 3.9s blocking → 35 frames / 2.3s / 1.7s**. At or below 60 it stays 1:1.
- **Camera is overview-first:** if the whole workspace fits at `OVERVIEW_MIN_K` or better it frames everything; only a workspace too large to read whole falls back to the active note's neighbourhood. It tracks the layout while it unfolds until you pan, zoom or drag. Breathing room is reserved in **screen** pixels, because labels are drawn at a constant size.
- **Everything drawn is sized in screen pixels and divided by the zoom** — dots, strokes, arrowheads, labels, folder chips — so zoom changes how far apart notes are, not how big a note looks. Two deliberate exceptions: dots are damped below 1× (constant dots turn a zoomed-out map into touching circles), and folder container geometry is world-stable below 1× (screen-sized padding inflated every box in world terms when zoomed out).
- **NO TEXT IS EVER DRAWN OVER.** `placeLabels` (pure, unit-tested) resolves every label in screen space against everything already placed — every node dot, then every folder chip, then ghost stubs. Each name gets **four candidate positions** and then a **compact form**; a label is vetoed if it would cross a container the note does not belong to, or fall off the canvas. Dropping a label is the only sanctioned outcome, and the note is still named in the rail and on hover. Re-measured in a browser across 3/12/25/40/153-note workspaces, desktop and phone widths, at fit / 4 clicks out / 8 clicks in.
- **Folder containers have ONE geometry definition — `folderRects`** — shared by the renderer, the label placer and the layout forces (they each used to compute their own approximation, so the box you saw, the box labels avoided, and the box clusters were pushed out of were three different rectangles). A container encloses each member's dot **and its label**. Separation is a **hard positional constraint** applied after integration, not a force that loses to the springs. The cluster's chip straddles a border, fieldset-legend style, and slides along it looking for clear ground.
- **`chip↔dot` is NOT zero and cannot be.** Below ~40% zoom the dots converge into a band by design and a screen-constant chip covers a lot of world, so no border slot is clear; measured, a chip's own letters sat under a node dot. The resolution is **draw order** — containers paint first (a background wash), then edges and nodes, then **folder chips LAST**, so the cluster name wins the pixel. `graph-metrics.test.js` pins that source order.
- **The rail is the whole information layer.** With a node selected: title, folder/state tags, three stat cells (links in · out · headings), Open/Focus/Isolate, the document's **headings** (click one to open the note there), **both link directions as clickable documents**, and that note's broken links — counts alone said a relationship existed but not with what. With nothing selected it is a workspace overview (most connected, unlinked notes, broken links), so the header counts lead somewhere real.
- **Search & health filters:** a header search dims non-matches (the layout never re-simulates; Enter focuses the match) and orphan / broken-link chips filter the map, with an off-by-default ghost-target overlay for missing link targets. Metrics come from the pure, unit-tested [src/store/graph-metrics.ts](../src/store/graph-metrics.ts) (`findOrphans`, `rankByDegree`, `brokenLinks`, `placeLabels`, `folderRects`, `stepsPerFrame`); broken data is passed in from `linkIndex.unresolved`.
- **Zero-edge state:** when there are nodes but no links, the map replaces the scatter of unconnected dots with an explanation of what a link is plus clickable chips for each note — a dot field reads as broken.
- **Navigation:** click = select, double-click / **Enter** = open (closes the overlay), drag = rearrange, wheel / footer buttons / **Fit** = camera.
- **Accessibility:** nodes are focusable (`role="button"`, Enter to open) with a focus ring, and an `sr-only` list mirrors every node. The overlay is a labelled **region**, not a modal — the menu bar, workspace panel and surface switcher stay usable beside it by design, and the covered editor is marked `inert` instead.
- **Entry points:** the **Editor · Cards · Map** switcher in the top bar, **View ▸ Relationship map**, **⌘⇧G**, and the `/graph` route. **Escape** clears an active search/filter first, then closes — but only an Escape meant for the map: it is handled in the bubble phase (`overlayShouldHandleEscape`, [src/ui/overlay-escape.ts](../src/ui/overlay-escape.ts)), so one pressed in a dialog or menu over the map, or in a library rename box beside it, stays with that control. The graph's **JSON export** lives in the map's own header (it used to sit in the global status bar, visible to people who had never opened the map). Node/edge data from `exportGraph` ([src/store/link-index.ts](../src/store/link-index.ts)); [src/ui/GraphView.tsx](../src/ui/GraphView.tsx).
- **Testing hooks:** the DOM carries `pf-node-dot` / `pf-node-label` / `pf-folder-box` / `pf-folder-chip` / `pf-chip-label` / `pf-ghost-label` classes plus `data-doc-id` / `data-folder-docs`, specifically so overlap can be **measured** in a browser rather than eyeballed. If you touch the geometry, re-measure.

### 17b. Cards board

- **What:** A Google-Keep-style board over the WHOLE library — every document is a card, with quick capture, checklists, nine note colours, pin-to-top, and search. An overlay over `<main>` with the live editor still mounted beneath ([src/ui/CardsView.tsx](../src/ui/CardsView.tsx) + pure helpers in [src/store/cards.ts](../src/store/cards.ts)).
- **Cards show RENDERED markdown, not raw source.** The face renders each note as real structure — headings, lists, emphasis, links — via `cardPreviewHtml`, a **pure, bounded** PM-JSON→safe-HTML renderer (deliberately not marked or `generateHTML`, which would build a ProseMirror schema per card on every search keystroke). Every text run is escaped and only a fixed structural tag whitelist is emitted; a link renders as an `<a>` with no href, since the card face is itself a button.
- **The opened card is a Preview · Split · Write surface** (persisted `pf:card-view`; default **Preview** on a phone, **Split** on a wide screen). Opening a note shows it *rendered*, not as raw `##` and `**`; Split puts the markdown source beside a live rendered pane; Write is the source alone. The rendered side reuses the app's own markdown engine and sanitizer (`sanitizeForIngest(engine.mdToHtml(...))`), so a card renders identically to the main preview and reflects unsaved edits as you type. Links in the rendered view are for reading — a click never navigates the board away; real navigation is **Open in editor**.
- **Still deliberately reduced.** No formatting toolbar in the card; full authoring is one click away. Editing hands **markdown** back to the host (`handleCardSave`), which parses with the live schema and writes through the same guarded path the host bridge uses — the card view never writes the canonical itself.
- **A card edit keeps the note's formatting.** The card's source comes from the **Styled** converter, so colour, highlight and font survive the round trip. Alignment, which Markdown cannot carry, is restored onto every paragraph and heading the edit left unchanged (`carryBlockAttrs`, [src/store/card-save.ts](../src/store/card-save.ts)), and you are told when edited ones lose it. When the note holds anything the round trip cannot carry, the version being replaced is snapshotted first. If another tab changed the note after the card was opened, the edit is refused and kept in Version history instead.
- **Quick capture** keeps its draft (`pf:card-draft`) across closing the board and reloads: Escape collapses the composer and keeps the draft, and only Cancel discards it. Capturing is a document-leaving path — the open document is flushed and saved first, and the editor returns to it afterwards.
- **The board keeps up without blanking:** it reloads incrementally (`planCardReload` re-reads only new or changed notes, so the board and its scroll position stay put), shows skeletons only on the first load, renders 60 cards at a time as you scroll, and applies pin and colour at once. Escape closes the most specific thing first — the colour menu, then an open card (saving it, as Done does), the composer, the search, and only then the board — and is handled in the bubble phase, so an Escape pressed in a confirmation dialog stays with the dialog.
- Pure helpers (preview, checklist, colour/pin, sort/filter) are unit-tested in [src/__tests__/cards.test.js](../src/__tests__/cards.test.js).

## Structured content — deprecated extensions (not in the editor)

`FieldBlock`, `TransclusionBlock` and `BlockId` are **exported by the npm package for compatibility only**. The editor registers them in **neither** its live schema ([src/ui/TiptapPane.tsx](../src/ui/TiptapPane.tsx)) **nor** the headless serializer (`SERIALIZE_EXTENSIONS`, [src/engine/serialize-doc.ts](../src/engine/serialize-doc.ts)), and the engine never turns on the preprocessor passes that would produce them (`fieldBlocks`, `transclusions`, `blockIds` in [src/engine/preprocessor.ts](../src/engine/preprocessor.ts) are all off). The package re-exports each as a copy that logs one console warning, in development builds, when an editor is created with it; they still work in a Tiptap editor of your own and will be removed in a future major version (see the README's *Deprecated* table). What each is, and what its syntax does in this editor:

### 18. Field blocks (`:::fields … :::`)

- **What (in your own Tiptap editor):** structured key→value metadata rendered as a card — [src/extensions/FieldBlock.ts](../src/extensions/FieldBlock.ts), `parseFieldBlock` ([:75](../src/extensions/FieldBlock.ts#L75)), `serializeFieldBlock` ([:96](../src/extensions/FieldBlock.ts#L96)).
- **In this editor:** `:::fields` lines are ordinary paragraph text.

### 19. Transclusions (`![[…]]`)

- **What (in your own Tiptap editor):** embed another document, or a section or block of it — [src/extensions/TransclusionBlock.ts](../src/extensions/TransclusionBlock.ts), `resolveTransclusions` ([:163](../src/extensions/TransclusionBlock.ts#L163)) resolves targets recursively and detects circular references.
- **In this editor:** nothing is embedded — `![[Title]]` reads as a `!` followed by an ordinary wiki link.

### 20. Block IDs (`^block-id`)

- **What (in your own Tiptap editor):** per-block anchors — [src/extensions/BlockId.ts](../src/extensions/BlockId.ts), `extractBlockIds` ([:93](../src/extensions/BlockId.ts#L93)), `assignBlockIds` ([:169](../src/extensions/BlockId.ts#L169)). The ids do not survive a Markdown round trip.
- **In this editor:** a trailing `^abc123` is ordinary text.

Chosen from View ▸ Appearance and Settings ▸ Appearance ([src/ui/ThemeControls.tsx](../src/ui/ThemeControls.tsx)).
- **Entry point:** `next-themes` `ThemeProvider` in [src/main.tsx](../src/main.tsx) (storage key `perssonify-theme`); palettes in [src/theme/palette.ts](../src/theme/palette.ts); class strings from `createTheme` ([src/theme/index.ts:32](../src/theme/index.ts#L32)).
- **Contrast:** text in the accent colour uses a contrast-tuned token (`text-primary-strong`, 4.5:1 or better in every palette and theme), keyboard focus shows a 2px `--focus-ring` outline, and Windows high-contrast (forced colours) restates every background-only state in system colours.

### 23. Responsive layout

- **What:** Every view mode is available at every width. Below 768px the menu bar collapses to ☰ and Split stacks its panes when there is height for two (see #2); the toolbar compacts by its own measured width; safe-area insets for notched devices; below 450px of height the standalone shell scrolls rather than squeezing the editor to nothing.
- **Entry point:** [src/hooks/use-mobile.ts](../src/hooks/use-mobile.ts), [src/ui/split-layout.ts](../src/ui/split-layout.ts), `TOOLBAR_COMPACT_BP` ([src/constants.ts](../src/constants.ts)).

## Viewing, sharing & embedding

### 24. Read-only mode

- **What:** Opens the document non-editable: both panes go read-only, the formatting toolbar is hidden, and the **view mode is locked** (Markdown/Rich/Split can't be changed until read-only is turned off). The menu bar and reading stay available.
- **Entry point:** state `useUIStore.readOnly` (localStorage `pf:read-only`). Panes honor it via `editor.setEditable` (Tiptap) and an editability Compartment (`EditorState.readOnly`/`EditorView.editable`, CodeMirror). The view-mode lock lives in [src/ui/ModeSwitcher.tsx](../src/ui/ModeSwitcher.tsx), the View menu ([src/ui/MenuBar.tsx](../src/ui/MenuBar.tsx)), and the Settings selector ([src/ui/SettingsSheet.tsx](../src/ui/SettingsSheet.tsx)).
- **Toggle:** View menu, File → Settings, or the `readonly=true` URL param. Read-only is re-applied to the markdown pane after every document switch, and it also disables Restore, As new and Delete in Version history. A document written by a newer build of the app is opened read-only automatically (session-only, never saved as your setting; it lifts when you open a document this build can edit).

### 25. Placeholder ad slots (development builds only)

- **What:** "Your Ad Here" placeholder slots for layout work. They render **only in a development build** (`adsAvailable`, [src/utils/build-gates.ts](../src/utils/build-gates.ts)) — checked where the slots render, so a stored `pf:show-ads` from an older version or a crafted `?ads=1` link cannot put them in a shipped build. Never shown in the embed; gated by `useUIStore.showAds` AND full chrome as well.
- **Entry point:** [src/ui/AdUnit.tsx](../src/ui/AdUnit.tsx). Slots are placeholder-only (no external network — offline/CSP-safe).
- **Toggle (development builds):** View menu, Settings ▸ Admin, or the `ads=true` URL param. In a production build none of these is offered, and `?ads=` is ignored (still stripped from the address bar).

### 26. Share / embed link builder

- **What:** Tools ▸ Share / embed link composes a standalone link (settings pre-applied) and an `<iframe>` embed snippet from a few toggles — view mode, read-only, import URL, theme, accent, chrome, background (and, in development builds only, ads). The same builder is rendered inline on the Help page.
- **Entry point:** [src/ui/LinkBuilder.tsx](../src/ui/LinkBuilder.tsx) (the one builder), wrapped in a dialog by [src/ui/LinkBuilderDialog.tsx](../src/ui/LinkBuilderDialog.tsx). Only enabled parameters are written, so links stay short; links target the app root.

### 27. Standalone URL parameters

The app reads these on load and strips them via `history.replaceState` ([src/App.tsx](../src/App.tsx)):

| Param | Values | Effect |
|-------|--------|--------|
| `view_mode` | `md`\|`html`\|`split` | initial pane(s); mapped to `setMode` |
| `readonly` | `true` | open read-only (locks the view) |
| `ads` | `true` | show the placeholder ad slots — **development builds only**; ignored (but still stripped) in production |
| `import_url` | `<link>` | **pre-fills** the importer with that link (top-level only). It never fetches on its own — a shared link must not make a visitor's browser call an attacker-chosen address on load. |

The iframe embed ([src/embed.tsx](../src/embed.tsx)) additionally reads `theme`, `accent`/`accentColor`, `chrome`, `bg`, and `allowed_origin` — the origins permitted to drive it over `postMessage` (never a literal `*`). Which origin it finally trusts is decided by `resolveEmbedAllowedOrigins` ([src/integration/embed-origins.ts](../src/integration/embed-origins.ts)): a deploy-time allowlist has the last word, and where the browser reports the real framer the origin must be that framer — see [integration-guide.md](integration-guide.md#cross-origin-iframe-embeds). `view_mode` there is aliased to `mode`; the embed does not apply `ads`.

### 28. Password-protected archive import

- **What:** Importing an encrypted `.zip` (by file or URL) is detected with no dependency (central-directory general-purpose bit 0), prompts for a masked password, and decrypts in-browser via a lazy `@zip.js/zip.js` import. Wrong password re-prompts.
- **Entry point:** `isZipEncrypted`/`extractArchive` in [src/store/archive.ts](../src/store/archive.ts); `ArchiveEncryptedError`/`ArchiveWrongPasswordError`. Prompt uses `useDialog().prompt({ type: "password" })`.

## Editor UX details

### 29. Heading-anchored scroll sync (split view)

- **What:** In split view the two panes stay aligned by a **heading-anchored piecewise-linear** map: corresponding headings on both sides are paired and interpolated between, so each section's scroll speed scales to its own relative height (a global percentage only kept top/bottom aligned). Value-based echo suppression (no timer). Falls back to top↔bottom when a doc has no headings.
- **Entry point:** [src/ui/EditorPanes.tsx](../src/ui/EditorPanes.tsx) (`project`/`rebuild`). CM anchors via `lineBlockAt(line.from).top` (works for off-screen lines); rich anchors via heading `getBoundingClientRect`.

### 30. Image rendering & sizing

- **What:** Editor and preview images render **full, with no border-radius** (rounding clipped corner pixels and truncated logos/screenshots with edge content). Images can be sized with an `<img … width="…" />` tag (`extensions/SizedImage.ts`), and follow the in-app theme via `#gh-light-mode-only`/`#gh-dark-mode-only` fragments or a `<picture>` element (`extensions/ThemeImage.tsx`). Insert ▸ Image…, the toolbar and the right-click menu ask for the URL and then a description (`promptImage`): the alt text, where an empty answer marks the image decorative; the markdown pane writes `![alt](src)` with the URL given. A remote image loads from its host unless Settings ▸ Privacy ▸ Block remote images is on.
- **Entry point:** `.ProseMirror img` in [src/styles.css](../src/styles.css) + `[data-md-preview] img` in [src/engine/useMarkdownEngine.ts](../src/engine/useMarkdownEngine.ts).

### 31. Graceful mode transitions

- **What:** Imposing a view mode, read-only or focus mode briefly fades the editor area (`pf-mode-fade`, opacity-only, restarted via reflow — no remount) so panes/toolbar don't snap in and out.
- **Entry point:** [src/ui/EditorPanes.tsx](../src/ui/EditorPanes.tsx) effect on `[mode, readOnly, focusMode]`; keyframes in [src/styles.css](../src/styles.css).
